# Travel Safety Advisor — Corrected

## What was wrong

1. **Data leakage in training.** `cluster` and `safe_or_unsafe` (a text
   column) were left in as training features, but both are literally
   derived from the target column (`safe_or_unsafe_binary`). The old
   model wasn't predicting anything — it was reading the answer straight
   off two duplicate columns. That's why it looked "accurate" during
   training but behaved randomly in the app.
2. **The app never collected most of the model's inputs.** The trained
   model needs 27+ features (state, district, date, case counts,
   coordinates, weather, health flags), but `final.py` only had UI for 4
   of them and silently set every other feature — including state,
   district, and case counts — to `0` before predicting. So even a
   correctly-trained model would have gotten nonsense input.
3. Hardcoded Windows-only paths (`D:\ML_Project\...`) in `app.py` and
   `save_model.py`, an incomplete `app.py` stub, and a `travel.py` that
   crashed on any state/district not seen during training.

## What's new here

- `train_model.py` — retrains the model with the leaked columns removed,
  a real train/test split, `class_weight="balanced"` for the ~80/20
  class imbalance, and prints an honest classification report instead of
  leaked ~100% accuracy.
- `app.py` — single, working Streamlit app. Collects every feature the
  model needs (via dropdowns for state/district, a date picker, weather
  auto-fetch with manual fallback, and all health-condition checkboxes),
  so nothing gets silently zeroed out.
- `saved/metrics.txt` — the real evaluation numbers from the last
  training run, so you can see (and reproduce) actual model performance.

## ⚠️ Important note on the numbers you'll see

After removing the two leaked columns, the model still scores ~100%
accuracy. That's *not* leakage this time — it's because this dataset's
safety label was generated by a deterministic rule over a handful of the
health flags (e.g. `skin_disease=1` or `low_bp=1` always maps to
"unsafe" in the data; `asthma=0` always maps to "safe"). Check
`saved/metrics.txt` → feature importances to see this. In other words:
**this dataset was built with a fixed rule, not noisy real-world
outcomes**, so a model trained on it will always look perfect. If you
want the model to reflect genuine epidemiological uncertainty rather
than the rule the data was generated with, you'll need real-world
labeled outcome data (e.g. actual traveler incident reports) rather than
this synthetic CSV.

## How to run

```bash
pip install -r requirements.txt

# 1. (Re)train the model — only needed if you change the data or want fresh artifacts
python train_model.py

# 2. Launch the app
streamlit run app.py
```

Your OpenWeatherMap key goes in `.env`:
```
OPENWEATHER_API_KEY=your_key_here
```
